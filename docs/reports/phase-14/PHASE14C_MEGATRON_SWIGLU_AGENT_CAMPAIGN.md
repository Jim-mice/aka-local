# Phase 14-C — Megatron SwiGLU Agent Campaign

## Verdict

**PASS for the first sidecar Agent campaign.** The campaign used the real Megatron-derived activation boundary only. Three real Codex Agent episodes ran on the V100 evaluator; two passed contract/compile/correctness, one was rejected for correctness. No Megatron upstream file was changed and no candidate was promoted into Megatron.

## 1. Frozen replacement boundary

The replaceable scope is **A: activation/gating subgraph only**:

```text
intermediate_parallel
  -> optional bias add
  -> split gate/up on last dimension
  -> SiLU(gate)
  -> multiply by (up + glu_linear_offset)
  -> activated intermediate
```

FC1 GEMM, FC2 GEMM, TP collectives, Transformer Engine, FP8 scaling, dropout, and residual BDA are excluded. The source-grounded boundary is recorded in `replacement_boundary.json` and frozen in `optimization_contract.json`.

The Phase 14-B ~626 µs value measured complete `MLP.forward` and is not directly comparable to this campaign. This campaign times only the activation subgraph for both trusted PyTorch baseline and candidate.

```cpp
    const half* intermediate, const half* bias, half* activated,
    int rows, int width, float glu_linear_offset);
```

## 5. Fixtures and trusted reference

Fixtures are deterministic metadata derived from Phase 14-B: seed `14`, FP16, TP=1, hidden size 1024, FFN hidden size 4096, `bias=null`, offset `0.0`. FC1 output is generated by the real Megatron MLP adapter outside timing. Metadata is in `targets/megatron_5be9626/swiglu/fixtures/fixture_metadata.json`.

The trusted baseline is PyTorch `chunk + torch.nn.functional.silu + multiply`, with the same fixed intermediate tensor and no FC1/FC2 GEMM inside timing. It matches the exact selected Megatron branch semantics.

## 6–8. Timing and methodology

Outside timing: imports, model construction, parameter initialization, input generation, FC1 fixture generation, allocation, and warmup.

Inside timing: only the activation subgraph from fixed `intermediate` to `activated`. CUDA events synchronize before and after; five samples of 100 iterations are recorded per shape. Mean, standard deviation, CV, and geometric-mean speedup are stored in each `result.json`.

Representative Episode 2 v1 baseline/candidate results:

| `[64,2,1024]` | 67.23 | 32.56 | 2.065x | 0.000488 |
| `[128,2,1024]` | 91.84 | 53.32 | 1.723x | 0.000488 |

Episode 2 geometric mean: **2.799x**. Correctness passed all shapes under FP16 `atol=0.002`, `rtol=0.002`.

## 13–15. NSYS and diagnostics

Exact profile command:

```text
<REMOTE_HOME>/tools/nsys-2026.2.1/target-linux-x64/nsys profile --trace=cuda,nvtx,osrt --sample=none -o /tmp/aka_swiglu_ep1_nsys <REMOTE_HOME>/venvs/lerobot-act/bin/python /tmp/aka_swiglu_eval.py --candidate /tmp/aka_swiglu_ep1.cu
```

Episode 1/2 profiles show:

- baseline: separate PyTorch SiLU, add, and multiply kernels;
- candidate: one `<unnamed>::swiglu_kernel`;
- candidate kernel launch instances: 1533 in the profiled run;
- candidate kernel total GPU time: approximately 53.15 ms in Episode 1 profile;
- separate baseline elementwise totals: approximately 43.24 ms SiLU + 34.42 ms add + 18.70 ms multiply in the same combined profile.

The conservative diagnosis is `MULTI_KERNEL_OVERHEAD`, based on named kernel and launch evidence. No memory-bound claim is made. Diagnostics are stored per episode in `diagnostic.json`.
