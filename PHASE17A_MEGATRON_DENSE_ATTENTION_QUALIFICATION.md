# Phase 17-A — Megatron Dense Attention Qualification

## Verdict

`QUALIFIED_FOR_AGENT_CAMPAIGN` for a precisely scoped, non-TE target:

**Megatron Native DotProductAttention (unfused local core)**.

This is not a claim that a universal “Dense Fused Attention” operator exists on
this host. The selected real path is `DotProductAttention`; Transformer Engine
and flash-attn are unavailable. No Agent candidate was generated in Phase 17-A.

## 1. Historical target ambiguity and source map

Phase 14-A correctly identified that “Dense Fused Attention” conflates the
attention block with its core. At commit `5be9626709af2722333bf54797c954c09edeada3`,
the source chain is:

```text
TransformerLayer.forward
  -> Attention.forward
     -> QKV projection / QKV layout / optional rotary embedding
     -> Attention._run_core_attention
        -> DotProductAttention.forward
           -> torch.baddbmm (scaled QK^T)
           -> FusedScaleMaskSoftmax
           -> torch.nn.Dropout
           -> torch.bmm (P V)
     -> output projection
```

The exact machine-readable map is in
`targets/megatron_5be9626/megatron_native_dot_product_attention/source_map.json`.
QKV and output GEMMs are not part of the selected core boundary.

## 2. Backend decision and environment audit

The read-only V100 probe recorded PyTorch `2.7.1+cu118`, CUDA `11.8`, and
`sm_70`. `transformer_engine` and `flash_attn` are not importable. PyTorch
SDPA exists, but the real Megatron probe does not dispatch to SDPA; it
constructs and executes `DotProductAttention`.

| Backend | Result | Evidence |
|---|---|---|
| Megatron `DotProductAttention` | AVAILABLE / selected | Real forward and backward replay |
| `TEDotProductAttention` | DEPENDENCY_BLOCKED | Transformer Engine unavailable |
| flash-attn backend | DEPENDENCY_BLOCKED | `flash_attn` unavailable |
| PyTorch SDPA | AVAILABLE but not selected | API probe only; not the Megatron module executed |

The probe uses a real Megatron process-group setup and initializes the
Megatron global memory buffer and model-parallel RNG tracker required by the
native module. It is not a handwritten attention proxy.

## 3. Canonical semantics and boundary

The primary contract is dense, no-mask, dropout-free attention:

```text
Q, K, V: [S, B, 16, 64], contiguous FP16
scale = 1 / sqrt(64) = 0.125
scores = Q K^T * scale
P = softmax(scores), with attention_softmax_in_fp32=True
P_drop = P because dropout probability is 0
O = P_drop V
output: contiguous [S, B, 1024] FP16
```

`attention_mask=None` is used for the primary dense contract. Causal,
padding, arbitrary-mask, nonzero-dropout, packed-sequence, and TE paths are
separate contracts and were not silently substituted. Nonzero dropout would
require versioned CUDA RNG and saved-mask/state semantics; it is excluded
from this qualification boundary.

The exact replay contract is
`targets/megatron_5be9626/megatron_native_dot_product_attention/replay_contract.json`
with hash `65058b45af7fb867a135d143b06e6600f75fbe7a13c523f351eef20d48741736`.

## 4. Shapes, layouts, and assumptions

Representative configurations are explicit model assumptions, not checkpoint
claims:

| S | B | hidden | heads | head dim | Q stride observed |
|---:|---:|---:|---:|---:|---|
| 16 | 1 | 1024 | 16 | 64 | `[1024,1024,64,1]` |
| 64 | 2 | 1024 | 16 | 64 | `[2048,1024,64,1]` |
| 128 | 2 | 1024 | 16 | 64 | `[2048,1024,64,1]` |

Megatron reshapes the core operands to `[B*heads,S,head_dim]`, computes score
matrices `[B*heads,S,S]`, then returns `[S,B,hidden]`. Tensor parallelism and
context parallelism are not part of this local single-process qualification;
the native module asserts context parallel size 1.

## 5. REAL replay and correctness

The real module was run for all three configurations. The output shape and
dtype were `[S,B,1024]` and `torch.float16`; the module was
`DotProductAttention`; the observed scale was `0.125`; no collective was
launched.

Against an independent FP32 score/softmax/PV oracle cast to FP16, maximum
forward absolute errors were `0.001465`, `0.001465`, and `0.001221` for the
three configurations. Relative error is not a useful primary FP16 diagnostic
near zero outputs, so the report retains absolute error and the frozen
`0.005` tolerance.

Real autograd backward executed through the same Megatron module. Independent
FP32 oracle dQ/dK/dV maximum absolute differences were:

| S×B | dQ | dK | dV |
|---|---:|---:|---:|
| 16×1 | 0.001225 | 0.001431 | 0.001301 |
| 64×2 | 0.001336 | 0.001801 | 0.001901 |
| 128×2 | 0.001383 | 0.001501 | 0.002116 |

These pass the qualification tolerance for the actual FP16 path. A separate
tiny FP64 finite-difference check of the same equations produced absolute
error `6.71e-11`.

## 6. Saved state and dropout

The native path relies on the PyTorch autograd graph generated by its real
operations: score matmul, softmax, dropout identity, context matmul, and
layout operations. No standalone fused saved-state ABI was activated. The
primary contract uses dropout `p=0.0`, but the code still requires the
Megatron model-parallel RNG tracker because the native implementation enters
its tracker context. A future nonzero-dropout campaign must freeze RNG
consumption and replay the same mask/state; independent draws are invalid.

Performance contract hash:

The intended forward boundary is preallocated Q/K/V and output completion for
the native core only. It excludes QKV GEMM, rotary preparation, output GEMM,
module construction, fixture allocation, and backward. Forward qualification

## 8. REAL NSYS evidence and kernel graph

REAL NSYS captured exact NVTX ranges at `S=64,B=2`, with separate forward and
backward runs. The forward range contained no NCCL and showed six CUDA kernel
launches in the captured call, including:

- two Volta FP16 GEMM kernels for QK and PV;
- the Megatron softmax warp kernel;
- FP16/direct-copy and conversion elementwise kernels.

The backward range contained no NCCL. It showed the expected transposed
GEMMs, `softmax_warp_backward`, elementwise multiply/conversion kernels, and
autograd-related launch/allocation activity. The captured forward NVTX range
was approximately 2.378 ms at this profiled invocation; this is trace
evidence, not a replacement for the event-sample statistics above. NSYS
exported GPU kernel summaries and CUDA API summaries; NCU metrics were not
used.

The raw artifacts are:

- `targets/megatron_5be9626/attention_phase17a_nsys_summary.json`
- `targets/megatron_5be9626/attention_phase17a_nsys_stats.json`

## 9. Diagnosis and headroom

Evidence-backed diagnosis: `MULTI_KERNEL_OVERHEAD` plus
`LOCAL_KERNEL_LATENCY`, with a material `SOFTMAX_KERNEL_OVERHEAD` component.
The selected path is not already one fused attention kernel: it launches
GEMMs, a softmax kernel, copies/conversions, and layout operations. This leaves
research headroom in eliminating surrounding pointwise/layout and softmax
launches, but does not justify claims about memory bandwidth, occupancy,
register pressure, or compute-bound behavior. Beating cuBLAS GEMMs is not
assumed to be the target.

## 10. Standalone attention comparison

Prior standalone dense/causal attention operators use different ABI and
benchmark assumptions. They do not necessarily use `[S,B,heads,head_dim]`,
Megatron's global score workspace, `FusedScaleMaskSoftmax`, model-parallel RNG
tracker, exact FP16/FP32 softmax settings, or the same saved autograd graph.
Their performance numbers are therefore not imported into this real-target
qualification.

## 11. Future candidate boundary and ABI

Research-only boundary metadata is in
`targets/megatron_5be9626/megatron_native_dot_product_attention/candidate_boundary.json`.
It permits replacement of scaled QK, dense no-mask softmax, p=0 dropout
identity, and PV, while excluding QKV/output GEMMs, rotary, nonzero-dropout
RNG, masked/causal modes, and TE. A future ABI must expose only semantic Q,
K, V, scale/mask mode, output, dimensions, and current stream; it must not
make Megatron's score workspace or other implementation temporary mandatory.
No ABI was activated and no Agent episode was generated.

## Final qualification

`QUALIFIED_FOR_AGENT_CAMPAIGN` for the native, dense, no-mask, p=0,
FP16 `DotProductAttention` core. The phase does not authorize an Agent
campaign itself; it establishes that a future campaign can be scientifically
scoped. A future Phase 17-B must freeze its own statistical policy and active
reference baseline before scoring candidates.

Remaining limitations are the unavailable TE/flash backends, unqualified
nonzero dropout and masked/causal contracts, explicit representative rather
than checkpoint-derived shapes, and the noisy backward qualification timing.
